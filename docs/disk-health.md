# 磁盘长期健康管理（C / D / E 盘）

> **给谁看**：想让系统盘长期不爆、但不想靠"感觉"清理的人。
> **什么时候看**：每月扫一眼，每季度认真清一次；或者 C 盘可用空间突然掉得很快时。
> **看完你能**：说清每个盘该放什么、知道哪些能安全清、避开六个"越省越糟"的操作。

---

## 0. 一句话原则

容量问题九成不是"盘太小"，而是**该在别处的东西堆在了系统盘、不该动的东西被当成缓存清了**。先分类，再清理。

---

## 1. 各盘该放什么（通用分配）

| 盘的角色 | 放什么 | 不要放 |
|---|---|---|
| **系统盘**（C:） | Windows、驱动、系统级程序（`Program Files`）、用户配置（`%APPDATA%`/`%LOCALAPPDATA%` 里体积不大的部分）、页面文件 | 大型数据、便携软件、下载堆积、虚拟磁盘、游戏 |
| **数据/程序盘**（D:） | 安装型程序（如 `D:\Apps\Installed`）、便携软件（`D:\Apps\Portable`）、IDE、项目与工作数据 | **唯一一份**重要数据（必须与别的盘或云互为备份） |
| **归档盘**（E: 或外置盘） | 冷数据、归档、备份（系统镜像、文件级备份）、媒体库 | 频繁读写的工作目录（但作为备份目标很合适） |

> 具体容量分配按你硬盘的实际情况定。本项目所在机器的实际布局与容量记录在[案例报告](case-report-d-apps-migration.md)的「本机现状速查」。

---

## 2. 关键认知：程序装到 D 盘 ≠ 省了 C 盘

很多程序的**数据与缓存仍然写在 C 盘用户目录**，装到别的盘只是搬走了程序本体。典型的三类：

| 类型 | 例子 | 数据通常落在 |
|---|---|---|
| 视频剪辑/创作类 | 剪映、各类剪辑与录屏工具 | `%LOCALAPPDATA%\<厂商>`（草稿、缓存、代理文件） |
| 办公套件 | WPS、Office 系第三方套件 | `%APPDATA%\<厂商>`（配置、云文件缓存、备份） |
| 浏览器 | 各类 Chromium 内核浏览器 | `%APPDATA%\<浏览器>`（配置、缓存、扩展） |

所以**做空间体检时必须同时看 `%LOCALAPPDATA%` 和 `%APPDATA%`**——那里往往是真正的大头，而且不在"设置 → 应用"里显示。

---

## 3. 空间体检：看什么、多久看、用什么

**节奏：每月看一次，每季度认真清一次。**

### 3.1 工具与分工

| 工具 | 用途 | 怎么用 |
|---|---|---|
| **WizTree** | 秒级扫出整盘占用排行（直接读 MFT 索引，比脚本递归快几十倍）。**体积统计这类活不该自己写脚本** | 图形界面直接看；需要脚本或人工核对时用命令行导出 CSV，见 3.2 |
| **Everything** | 秒级按名字定位文件：程序搬哪去了、机器上有几个同名 exe | 输入 `blender.exe` 秒出结果，比 `Get-ChildItem -Recurse -Filter` 快也更全 |
| **Geek Uninstaller** | 卸载 + 扫残留；**特别适合清"卸载器已失效/指向旧目录"的孤儿记录** | 按"大小/安装日期"排序 → 右键强制删除，比手写注册表删除安全 |
| **RegScanner** | 全注册表搜索（支持二进制/时间等条件），结果可导出 CSV | 查"哪个键还引用旧用户名/旧路径"时，比 `reg query /f /s` 快且好核对 |
| **Registry Finder** | 注册表**搜索 + 批量替换**（带预览） | 迁移后"旧路径 → 新路径"的批量改写，用它的预览复核更稳 |
| **Beyond Compare** | 目录/文件对比 | 迁移前后对比、**校验备份完整性** |

**分工建议**：先用 GUI 工具**快速定位/预览**（WizTree 看空间、Everything 找程序、RegScanner/RegistryFinder 搜索与替换预览），再用脚本**机械执行并留备份与日志**。别反过来——用脚本去做本该 GUI 一秒出结果的探索工作。

**交叉验证**：脚本给出的数字（体积排行、备份数量、改动条数）最好用手边工具复核一遍再下结论——只信脚本自述容易漏掉假阳性（例如"权限读不到"被当成"文件不存在"）。

### 3.2 WizTree 命令行（导出 CSV，供脚本或人工核对）

```powershell
# 目标路径是「位置参数」，导出用 /export=<文件>；不是 /path= 也不是 /exportfile=
& "D:\Apps\Portable\wiztree_4_31_portable\WizTree64.exe" `
    "C:\Users\<user>\AppData\Local" `
    /export="$env:TEMP\wiz.csv" /exportfolders /exportfiles /sortby=1 /admin
```

常用开关：`/exportfolders`、`/exportfiles`（分别导出目录行/文件行）、`/sortby=N`（0 不排序、1 大小、2 占用、3 修改时间）、`/exportmaxdepth=N`（只导出 N 层）、`/filter=*.mp4|*.mkv`、`/filterexclude=*.tmp`、`/admin`（提权走 MFT，整盘秒级）。

三个实测坑：

1. **别给参数套双重引号**：脚本里再包一层引号会让 WizTree 弹出一个**看不见的模态错误框**并卡住；PowerShell 里用数组传参最稳。
2. **CSV 第 1 行是横幅、第 2 行才是表头**；而且只有附加列是稳定的 ASCII 名，**前 7 列列名随系统语言变化**（中文系统是「文件名」）→ 解析必须**按列位置**，不要按列名。
3. **目录行以反斜杠结尾**（`…\AppData\Local\`），据此区分目录与文件。

### 3.3 该盯的阈值

| 指标 | 警戒线 | 低于/超过会怎样 |
|---|---|---|
| 系统盘可用空间 | **≥ 15% 或 ≥ 30 GB** | 低于 10% 会连带影响：Windows 更新、休眠/页面文件，以及**各安装器的临时解压**（多数安装器解压到 `%TEMP%`，在系统盘）——表现为"安装莫名其妙失败" |
| 可用空间下降速度 | **> 10 GB / 月** | 多半是某个应用的缓存或日志在涨，用 WizTree 定位 |

## 4. 可以安全清理的清单

| 位置 | 说明 | 做法 |
|---|---|---|
| `%LOCALAPPDATA%\Temp` | 临时文件 | 直接清（占用中的会跳过） |
| `%LOCALAPPDATA%\Package Cache` | 安装器缓存（**卸载/修复要用**） | **只清已卸载产品的**：看文件夹名的 GUID 对应产品还在不在"设置 → 应用"里；当前产品的缓存请保留 |
| 回收站 | —— | 确认后再清；这是唯一的"后悔药" |
| `C:\Windows\SoftwareDistribution\Download` | Windows 更新下载缓存 | 停 `wuauserv` 后清，或用磁盘清理 |
| `C:\Windows\Temp` | 系统临时 | 可清 |
| 休眠文件 `hiberfil.sys` | 通常是内存的 40%～100% | 不用休眠就 `powercfg /h off`（会失去"快速启动"） |
| 组件存储（WinSxS） | 更新残留 | `DISM /Online /Cleanup-Image /StartComponentCleanup`（安全，**别手工删 WinSxS**） |
| 卷影副本 / 还原点 | 可能占几十 GB | `vssadmin list shadowstorage` 看占用；在设置里限制还原点配额 |
| 浏览器缓存 | —— | 浏览器内清理 |
| 应用自己的缓存 | 剪辑草稿缓存、聊天软件接收的文件、下载工具缓存 | **先看清再删**（很多其实是你的数据） |

> **一条纪律**：清任何"缓存"前先确认它是否含**用户内容**。看着像缓存、其实是用户数据的情况非常常见（例如剪辑软件的草稿目录），这类一律**先送回收站**而不是直接删。
>
> 但请记住：**送回收站 ≠ 释放空间** —— 它只是"推迟决定"（本机那份 934 MB 的剪辑草稿，就是后来清空回收站才真正释放的）。要么在清理记录里注明"待清空回收站后才释放"，要么随后清空。

## 5. 不该做的"省空间"操作

| 别做 | 原因 |
|---|---|
| 手工删 `WinSxS`、`System32`、`ProgramData` 里的目录 | 会破坏组件服务与更新 |
| 把 `Program Files` 整体搬走 | 大量程序写死绝对路径，服务和驱动也会失效 |
| 用符号链接/junction 硬搬**会自动更新的程序**（浏览器、PowerToys、IDE 等） | 更新器往往忽略自定义位置，会把新版本装回默认目录，结果两套并存 |
| 用"剪切粘贴"移动程序目录 | 丢权限/时间戳，留半截文件；被占用的文件会静默失败 |
| 关闭页面文件 / 直接清空整个 `%LOCALAPPDATA%` | 前者影响崩溃诊断，后者等于重装所有应用 |
| **重命名用户目录（`C:\Users\<名>`）** | **最严重的坑**：改名后 `C:\Users\旧名\...` 在注册表里遍地都是，一大批软件的记录、关联、配置全部失效。要换用户名请**新建账户再迁移**——详见[迁移避坑清单](migration-checklist.md) |

## 6. 用户目录、页面文件、还原点的正确姿势

- **桌面/文档/下载/图片搬到别的盘**：资源管理器 → 右键该文件夹 → **属性 → 位置 → 移动**。系统会同步改注册表，安全。
  ❌ 不要"剪切粘贴"，❌ 不要用 junction 顶替。
- **页面文件**：系统盘紧张时可把主页面文件放到别的盘，但**给系统盘留一个小页面文件（如 2 GB）**，否则系统无法生成内核转储（蓝屏排障会失去线索）。
- **系统还原**：保留，但给它设配额（例如 5%）。它救过的人比占的空间值钱。

---

## 7. 备份：3-2-1，且必须验证

- **3** 份数据、**2** 种介质、**1** 份异地（另一块盘 + 云盘就是最简单的落地）。
- 每季度做一次**系统镜像**（换硬盘/崩系统时能省几小时到几天）。
- **注册表关键分支定期导出**（这也是安全动手改注册表的前提）：`Uninstall`、`App Paths`、`Classes` 下的关联与 CLSID、`Services`、`Run`。
- **没验证过的备份等于没有**：至少每半年**还原一个文件**试试能不能打开。

## 8. 例行节奏表

| 周期 | 做什么 |
|---|---|
| 每周 | Windows 更新后**重启一次**（很多"删除/更新"要重启才生效——补丁与驱动残留尤其如此） |
| 每月 | 清 Temp/回收站/更新缓存；看系统盘可用空间；用 WizTree 扫一眼增幅 |
| 每季度 | 跑一次**引用体检**（本仓库 `scripts/health-check.ps1`，只读）；卸载不用的软件并用 Geek 清残留；`chkdsk D: /scan`（只读扫描） |
| 每半年 | `DISM /Online /Cleanup-Image /StartComponentCleanup`；`sfc /scannow`；磁盘 SMART/健康检查；做系统镜像；**抽验备份可还原** |
| 每年 | 大版本升级/换机前先做基线快照（见[迁移避坑清单](migration-checklist.md)阶段 1） |

---

## 9. 清理时的三条纪律

1. **先备份，后改动**：删文件前算好体积并确认；改注册表前先 `reg export`。
2. **区分"用户数据"与"程序残留"**：用户数据（草稿、书签、聊天记录、配置）→ 先送回收站；程序残留 → 可直接删。
3. **不确定就先看体积和修改时间**：用 WizTree/Everything 看清它是什么、多大、多久没动过，再决定。
